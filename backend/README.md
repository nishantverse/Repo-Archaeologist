# Repo Archaeologist

A zero-config CLI tool that scans a local repository and generates onboarding artifacts — a styled terminal report and a Kiro steering file — so new engineers (and AI coding agents) can understand a codebase in seconds.

## What it does

Point it at any repo and it will:

- Detect the framework, entrypoint, and tech stack from `package.json` and file structure
- Flag oversized files (>500 lines) and outstanding TODO comments with git age
- Identify dead npm dependencies (declared but never imported)
- Feed the actual source files to an LLM (Groq or Ollama) for a human-readable architectural summary
- Print everything in a styled terminal box
- Write a `.kiro/steering/archaeology.md` file into the scanned repo so Kiro's AI agent has architectural context loaded automatically
- Optionally start a local Express server (`--ui`) exposing the full analysis as JSON

## Requirements

- Node.js 18+
- A Groq API key (free at [console.groq.com](https://console.groq.com)) **or** a local Ollama instance

## Installation

```bash
git clone https://github.com/your-org/repo-archaeologist
cd repo-archaeologist/backend
npm install
npm link
```

`npm link` registers the `repo-archaeologist` binary globally so you can run it from anywhere.

## Configuration

Copy `.env.example` to `.env` and fill in your settings:

```bash
cp .env.example .env
```

```env
# Choose your LLM provider: "groq" or "ollama"
LLM_PROVIDER=groq

# Groq (cloud) — get a free key at https://console.groq.com
GROQ_API_KEY=your_key_here

# Ollama (local) — if using LLM_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=llama3

# How much of the codebase to send to the LLM (~tokens)
# Groq free tier: keep at 6000 or below
# Larger paid tiers or Ollama: 8000–24000 is fine
LLM_CONTEXT_TOKENS=6000
```

The `.env` is loaded from the package directory automatically, so it works regardless of where you run the command from.

## Usage

**Scan the current directory:**
```bash
repo-archaeologist .
```

**Scan any repo by path:**
```bash
repo-archaeologist /path/to/your/repo
```

**Start the JSON API server after scanning:**
```bash
repo-archaeologist /path/to/your/repo --ui
# → 🔍 UI Server running at: http://localhost:38427
# → GET /api/analysis returns the full payload as JSON
```

**Invalid path exits cleanly:**
```bash
repo-archaeologist /nonexistent/path
# Error: "/nonexistent/path" does not exist or cannot be accessed.
# exit code 1
```

## Generated steering file

After each run, `.kiro/steering/archaeology.md` is written (or overwritten) inside the scanned repo. It includes the YAML front matter `inclusion: auto` so Kiro loads it automatically as context for every AI session in that workspace.

```markdown
---
inclusion: auto
---

# Repository Architecture (Generated by Repo Archaeologist)

## Data Flow
Browser → React App → REST API → Database

## Onboarding Summary
...

## Tech Debt
...

## Architectural Constraints
...
```

## LLM providers

### Groq (recommended)

Set `LLM_PROVIDER=groq` and add your `GROQ_API_KEY`. The free tier supports up to 12,000 tokens per minute. Keep `LLM_CONTEXT_TOKENS` at `6000` or below to stay within the limit.

Default model: `llama-3.3-70b-versatile`. Override with `GROQ_MODEL=<model-name>`.

### Ollama (local / offline)

Set `LLM_PROVIDER=ollama`. Make sure your model is pulled before running:

```bash
ollama pull llama3
```

Then set `OLLAMA_MODEL=llama3` in `.env`. Point `OLLAMA_BASE_URL` at your instance if it's not running on the default `http://localhost:11434`.

Note: small models (1B–3B) may produce lower-quality summaries. `llama3` (8B) or larger gives much better results.

### No LLM / offline fallback

If no provider is configured or the API call fails, the tool falls back to deterministic output — framework-appropriate data flow, a template summary, and generic constraints — and prints a warning. The heuristic scan (tech debt, dead deps) always runs regardless.

## Architecture

```
bin/index.js              CLI orchestrator — arg parsing, pipeline wiring
src/
  constants.js            Shared constants (ignore list, framework map, thresholds)
  heuristics/
    entrypoint.js         Stack & entrypoint detection from package.json / file system
    techDebt.js           MegaFile + TODO detection with git age lookup
    deps.js               Dead dependency scanner
  llm/
    analyzer.js           Groq / Ollama integration + deterministic fallback
  output/
    terminal.js           Boxen terminal renderer
    steeringFile.js       .kiro/steering/archaeology.md writer
  server/
    uiServer.js           Ephemeral Express server (--ui flag)
  utils/
    walkDir.js            Shared async recursive directory walker
```

The pipeline runs in three phases:

1. **Heuristics** — `entrypoint`, `techDebt`, and `deps` run in parallel via `Promise.all`
2. **LLM synthesis** — actual source files are packed into the context window and sent to the configured provider
3. **Output** — terminal render, steering file write, optional UI server
